# Персонал · CHEF’S BURGER

Разделът **Администрация → Персонал** съдържа регистър, график, присъствия, отсъствия, договори, ведомости и разходи. Всички суми са в евро. Часовете се въвеждат по местно време за София.

## Преглед за одобрение

В preview deployment отвори **/staff-review/index.html**. Примерният екип е отделен за всеки браузър. Промените се запазват в IndexedDB за този адрес. Прегледът изпълнява същите SQL миграции, заявки и компоненти чрез локален PostgreSQL (PGlite). Самоличността в този демонстрационен екран е фиксирана. Реалният административен панел проверява подписаната сесия на сървъра при всяка операция. Примерната страница се генерира само за preview или при изричната локална команда.

1. Избери служител от **Обзор**. В досието добави ставка с начална дата.
2. В **График** добави смяна или я премести с влачене. Отвори смяната за редакция от телефон. Копирането на седмица записва всички смени заедно. Един конфликт отменя целия запис.
3. В досието отчети началото и края или въведи реалните часове ръчно. Потвърди отчета, за да участва във ведомостта. При нощна смяна избери следващата дата за края.
4. Предложи бонус и го одобри или въведи вече одобрен финансов запис. Отчети аванс и частично плащане. Всяко плащане има отчетен месец, действителна дата, метод и основание.
5. След края на месеца въведи провереното нетно възнаграждение от ведомостта. Приключването заключва индивидуалния период. След това могат да се отчитат оставащите плащания.
6. В **Разходи** избери втори месец за сравнение. CSV файловете са UTF-8 с разделител точка и запетая. Регистърът предлага и Excel XML.

## Изолирана Neon среда

Създай отделен Neon branch или база за проверка. Използвай нейния адрес за preview променливата DATABASE_URL и задай CMS_ISOLATED_PREVIEW=true само за изолираната среда. Ако е напълно нова, първо приложи database/schema.sql за съществуващия CMS. Настрой ADMIN_EMAIL, ADMIN_PASSWORD_HASH и SESSION_SECRET според README на проекта.

Приложи миграциите в една и съща база в следния ред. Примерът очаква PREVIEW_DATABASE_URL да съдържа адреса на изолираната база.

```sh
for file in database/staff-00{1,2,3,4,5,6,7}.sql; do
  psql "$PREVIEW_DATABASE_URL" -v ON_ERROR_STOP=1 -f "$file" || exit 1
done
```

Всяка миграция е транзакционна и повторно изпълнима. 001 създава регистъра и историята му. 002 добавя договори, смените, отсъствията, финансовите записи и изчисленията. 003 добавя транзакционните операции с идентификатор за повторен опит. 004 добавя копиране на седмица и защити за историята. 005 добавя седмичните разходи и проверките на почивките. 006 добавя бюджети, дати за заплати и прогноза по график. Примерните данни се съдържат отделно в scripts/staff-review/seed.sql.

Собственикът използва съществуващия вход. За отделен оперативен мениджър настрой STAFF_MANAGER_EMAIL и STAFF_MANAGER_PASSWORD_HASH с различен имейл. Генерирането на хеша използва съществуващия scripts/make-password-hash.mjs. Мениджърът управлява графици, присъствия и отпуски. Финансовите операции, бележките и редакцията на регистъра изискват собственика. Самостоятелни служителски акаунти не са включени.

## Правила на ведомостта

- Потвърдените минути се изчисляват от реалния интервал минус почивката. Нощната смяна се отнася към местната дата на започване. При почасов договор се плаща по реалното времетраене. При дневен договор няколко отчета за деня носят един надник.
- Месечният режим разпределя договорената брутна сума по календарните дни за прогнозата. Ставката важи от въведената дата. Архивирането спира бъдещото месечно начисляване от следващия ден.
- Бонусите и одобрените доплащания увеличават прогнозното брутно. Добавките за празник, нощен и допълнителен труд се въвеждат като проверени суми. Платен отпуск, болничен, данъци, осигуровки и законови коефициенти изискват счетоводна проверка. Датите на отсъствие и предупредителните прагове сами по себе си не определят дължимото възнаграждение.
- До приключване оставащата прогноза е брутно минус одобрени удръжки, аванси и плащания. След приключване остатъкът използва потвърденото нетно минус аванси и плащания. Разходът е начислено брутно възнаграждение и не включва работодателски осигуровки.
- Седмичните суми се групират по местна бизнес дата. Финансовите добавки и плащанията се показват по действителната им дата за избрания отчетен месец. Закръглянето на отделните седмици може да даде разлика от цент спрямо целия месец.
- Препоръките за почивки използват часовете в индивидуалния договор. Целевият дневен брой служители се избира в календара. Разход спрямо оборот не се публикува, тъй като поръчките могат да използват отделна платежна база.

## Локална проверка

От корена на проекта изпълни npm install, npm run typecheck, npm run check:files, npm run test:cms, npm run test:staff и npm run build. За интерактивната демонстрация изпълни npm run staff:review и npm run dev, след което отвори /staff-review/index.html. PostgreSQL тестовете прилагат миграциите два пъти и проверяват начисления, конфликти, заключване, подписани сесии и разграничаване на правата.
